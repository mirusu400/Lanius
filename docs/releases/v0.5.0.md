# Lanius 0.5.0

This release adds deeper traffic inspection, more control over upstream
connections, and substantial performance improvements for large projects.
These changes are relative to [v0.4.0](v0.4.0.md).

## Highlights

- **Inspect and transform encoded data:** select text in HTTP History or Replay
  to open Inspector. Automatic detection can peel nested URL, Base64, hex, HTML,
  escape, gzip, and JWT layers; manual chains give precise control. Replay can
  apply an edit by encoding it back through the same chain while preserving
  details such as percent-escape case, Base64 padding, and hex separators.
- **Work smoothly with large histories:** capture persistence is batched and
  bounded, searches are faster and abandoned queries are cancelled, and large
  bodies use bounded server reads plus a virtualized viewer. Raw bodies stream
  without being buffered into one response, while Replay and Fuzzer load only
  the request they need. Startup, database migration, and project cleanup now
  show progress instead of appearing frozen.
- **Adapt HTTP History to the investigation:** switch between side-by-side and
  stacked layouts, reorder or hide columns, resize pages, sort by stable request
  number, override body character sets, and control wrapping and whitespace.
  Optional public-IP observation records address changes and can estimate the
  address used for each captured connection without making requests merely to
  display the column.
- **Control how Lanius reaches targets:** run multiple listeners in one project
  and select Auto, HTTP/1.0, HTTP/1.1, or HTTP/2 for upstream traffic. Replay and
  Fuzzer can override the project default, History records the protocol actually
  used, and forced HTTP/2 fails clearly when h2 was not negotiated. TLS failures
  now explain the certificate problem and support explicit exact-host exceptions
  or a project-wide verification override for authorised lab environments.
- **Build stronger Replay and Fuzzer workflows:** Replay follows redirects one
  hop at a time or automatically with loop and cross-origin credential guards.
  Fuzzer's Payload Maker generates numeric, character, and date inputs and
  applies ordered transformations locally. Browser-emulation Match & Replace
  presets, safer Intercept rejection handling, and more robust request-number
  allocation round out the testing workflow.
- **Extend Lanius with Plugin SDK 1.5:** plugins can contribute typed HTTP MCP
  tools and persistent workspace tabs, read exact bounded exchanges, perform
  atomic project-storage batches, request clipboard or download capabilities,
  and use host-provided styles with live theme changes. Plugin execution remains
  suspended in safe mode and Lockdown Mode. See
  [Plugin MCP Tools](../plugin-mcp.md) for the SDK 1.3 tool API and bundled sample.
- **Keep scope and Lockdown enforcement predictable:** scope rules can be edited
  completely in Target, capture is restricted to scope by default, and editable
  Google background-host exclusions reduce unrelated traffic. Effective
  Lockdown scope egress validates both the HTTP host and connection destination
  before allowing an outbound socket.
- **Improve desktop reliability:** startup Doctor identifies runtime, data-folder,
  CA, port, and proxy-start failures before opening a project. Dashboard shows
  project size, action toasts are configurable, external links open in the
  system browser, plugin views load reliably in WKWebView, and dependency
  versions include current Vite, rustls, and web PKI security fixes.

## Notable behavior changes

- New and existing projects default to not recording out-of-scope traffic and
  receive editable `*.googleapis.com`, `*.google.com`, and `*.gvt1.com` exclude
  rules once. Existing explicit capture choices and edited rules are preserved.
- HTTP History initially reads at most 256 KiB from each stored body. Use the
  next-chunk control or raw body endpoint when the complete body is needed; the
  original stored bytes are not discarded by this display limit.
- Sensitive request and response headers are visible by default in the local
  desktop UI. Built-in MCP tools continue to redact them unless explicitly
  asked to reveal secrets.

## Installation notes

The macOS and Windows packages are not signed by Apple or Microsoft. On macOS,
after installing the app, run
`xattr -dr com.apple.quarantine /Applications/Lanius.app` before the first
launch. On Windows, SmartScreen may require **More info** then **Run anyway**.
Debian packages use the download link for later upgrades; they do not replace
themselves through the in-app updater.

Lanius is for security testing of systems you are authorised to test.
