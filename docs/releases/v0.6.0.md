# Lanius 0.6.0

This release adds a visual attack-surface map, portable settings workflows,
and more direct control over Replay, Intercept, TLS, and upstream proxies.
These changes are relative to [v0.5.0](v0.5.0.md).

## Highlights

- **Explore targets as an interactive graph:** switch Target from the tree to a
  multi-host graph, drag and zoom nodes, inspect immediate child paths and their
  requests, and pause or resume the force layout. A shared 400-node display
  budget prioritizes the selected path and its neighbours so large projects
  remain responsive without removing any captured data.
- **Move settings between tools and projects:** export a capture-free Lanius
  settings file, then import it through the project picker, an open project, or
  drag and drop. Burp settings JSON can bring across target scope, HTTP Match &
  Replace rules, active proxy listeners, HTTP protocol preferences, capture
  restriction, and an unauthenticated SOCKS route. Lanius previews detected
  changes and skipped entries before applying them.
- **Search and edit requests faster:** Replay request editors now provide find,
  previous/next navigation, replace, and replace-all controls while preserving
  editor focus. Fuzzer highlights valid payload markers and treats unrelated
  closing braces as ordinary request text, so nested JSON and GraphQL bodies do
  not invalidate a marked request.
- **Control proxy authentication and TLS ciphers:** configure a username and
  password on each HTTP, HTTPS, or SOCKS5 upstream hop. Saved passwords can be
  retained without re-entering them. The TLS cipher manager lists suites the
  current engine supports and lets you search, add, remove, and reorder them
  without writing an OpenSSL cipher expression.
- **Operate Intercept from the keyboard:** toggle interception and forward the
  selected message with default shortcuts, or assign a shortcut to Drop. Replay
  and Fuzzer tabs can be reordered, and requests transferred between tools are
  visibly marked until their destination tab is selected.
- **Make application state clearer:** project and engine connection indicators
  distinguish a reconnecting engine from an unavailable one, while revised
  toasts and clipboard feedback avoid duplicate or misleading notices. Settings
  changes and destructive actions recover more cleanly from request failures.
- **Improve response fidelity:** response text, previews, and body chunks can
  repair one layer of UTF-8 that was mistakenly decoded as Latin-1 and encoded
  again. The repair is disclosed in the interface, applies only to read-only
  response display, and never changes the captured bytes or Replay request data.
- **Extend and contain plugins:** Plugin SDK 1.6 adds Target host context actions.
  Lockdown Mode now re-checks every plugin callback boundary, including actions,
  scanners, codecs, code generators, payload handlers, and managed tasks, so
  queued or previously registered plugin code cannot run while suspended.
- **Improve platform reliability:** Windows and Linux System Capture validate
  native privilege and platform requirements before saving a setting, certificate
  export uses the native Save As dialog, the built-in browser refuses to reuse a
  profile connected to an obsolete listener, and AppImage launcher permissions
  are checked during release builds. Python and UI dependency floors cover the
  current filelock, pyasn1, Tornado, OpenTelemetry, and front-end advisories.

## Notable behavior changes

- Target Graph displays at most 400 nodes across the selected hosts. This is a
  rendering limit only; paths and requests remain stored and accessible through
  the tree, host list, and request lists.
- Burp import uses an explicit allowlist. Credentials, client certificates, TLS
  bypasses, extensions, macros, scheduled tasks, and destination-specific
  upstream routes are not imported. Unsupported entries are counted in the
  confirmation instead of being applied approximately.
- Upstream proxy credentials are stored in the project database and therefore in
  complete SQLite backups. They are omitted from shareable JSON project and
  settings exports.
- Lockdown Mode suspends already loaded plugins as well as preventing new loads.
  Built-in codecs and code-generation formats remain available.
- A rejected Windows or Linux System Capture configuration is no longer saved.
  Live changes are reported as applied only after the native process filter is
  ready; macOS extension approval remains a separate state.
- Double-encoded UTF-8 repair is display-only. Request bodies retain their
  byte-reversible decoding so Replay never sends altered data.

## Installation notes

The macOS and Windows packages are not signed by Apple or Microsoft. On macOS,
after installing the app, run
`xattr -dr com.apple.quarantine /Applications/Lanius.app` before the first
launch. On Windows, SmartScreen may require **More info** then **Run anyway**.
Debian packages use the download link for later upgrades; they do not replace
themselves through the in-app updater.

Lanius is for security testing of systems you are authorised to test.
